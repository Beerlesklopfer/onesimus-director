Creates a temporary table in the catalog containing the selected files and directories for a restore job. The table is identified by the `path` handle, which is then used by the `restore` command to submit the actual restore job.

## Syntax

```
.bvfs_restore path=<handle> jobid=<N> [fileid=<id>[,<id>...]] [dirid=<id>[,<id>...]] [hardlink=<id>[,<id>...]]
```

## Arguments

| Argument | Description |
|----------|-------------|
| `path=<handle>` | Unique handle for the temporary restore table (e.g., `b21234`). |
| `jobid=<N>` | Job ID for the restore context. |
| `fileid=<id>` | Comma-separated list of file IDs to restore (from `.bvfs_lsfiles` output). |
| `dirid=<id>` | Comma-separated list of directory IDs to restore (from `.bvfs_lsdirs` output). |
| `hardlink=<id>` | Comma-separated list of hardlink IDs to include. |

## Examples

### Restore specific files
```
* .bvfs_restore path=b21234 jobid=42 fileid=100,101,102
BVFS restore: path=b21234 jobid=42 fileid=100,101,102
```

### Restore an entire directory
```
* .bvfs_restore path=b25678 jobid=42 dirid=5
BVFS restore: path=b25678 jobid=42 dirid=5
```

### Restore files and directories together
```
* .bvfs_restore path=b29999 jobid=42 fileid=100,101 dirid=5,12
BVFS restore: path=b29999 jobid=42 fileid=100,101 dirid=5,12
```

## Notes

- The `path` handle is generated by the client (WebUI, bconsole) and must be unique per session.
- After calling `.bvfs_restore`, use the `restore` command with `file=?<handle>` to submit the restore job.
- At least one of `fileid`, `dirid`, or `hardlink` should be specified.
- The temporary table persists until `.bvfs_cleanup path=<handle>` is called.
- Typical full workflow: `.bvfs_get_jobids` -> `.bvfs_update` -> `.bvfs_lsdirs`/`.bvfs_lsfiles` -> `.bvfs_restore` -> `restore` -> `.bvfs_cleanup`.
